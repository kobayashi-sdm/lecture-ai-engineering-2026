# 第3回：実行手順

## 準備

Python 3.12とuvが使える環境で、リポジトリの直下から実行する。Codespacesでは講座の設定をそのまま使える。

```bash
uv sync --frozen
```

`pyproject.toml` と `uv.lock` は講座の固定版を使用する。Geminiを呼び出す場合は、Codespaces secretに `GEMINI_API_KEY` を登録し、対象のforkへのアクセスを許可してからCodespacesを再起動する。

## APIなしで確認する

```bash
uv run pytest -q
uv run python -m app.agent --list-tools
uv run python -m scripts.check_lesson03
```

- テストは34件。APIキーもGeminiの利用枠も使わない。
- ツール一覧は `search_glossary`、`get_lecture_summary`、`make_quiz`、`save_learning_log` の4個。
- 検証スクリプトは呼び出しを固定した偽モデルを使い、実際の承認・保存・再開処理を実行する。テスト用の承認入力も固定している。
- 保存処理は一時ディレクトリの `learning_log/` で確認する。実行記録は `lectures/03/results/` に出力し、実際の学習記録は作らない。

Codespacesでは通常の `uv` を使用する。ローカルで実行する場合は、利用する環境にuvを導入する。

## Geminiで演習を確認する

```bash
uv run python -m app.ask "AIE2026の講座の宿題にある「3レベル」とは何ですか？"
uv run python -m app.agent --trace "AIE2026の講座の宿題にある「3レベル」とは何ですか？"
uv run python -m app.agent --trace "LoRAとQLoRAの違いは？"
uv run python -m app.agent --trace "第2回の内容から確認問題を1問出して"
```

回答の違い、`[tool call]` の名前と引数、`[usage]` の `requests` を確認し、`answer.md` の演習欄に実測結果を追記する。偽モデルの記録とは区別する。

## Geminiで保存の承認・拒否を確認する

```bash
uv run python -m app.agent --trace "第3回で『モデルがツール呼び出しを要求し、プログラムが承認後に実行する』と学んだので、この内容を学習記録に保存して"
```

1. 表示された講義回と内容を確認し、`y` を入力する。
2. `[tool return]` の保存結果と、`learning_log/` に作成されたJSONの内容を確認する。
3. 同じコマンドをもう一度実行し、今度は `n` を入力する。
4. ファイルが増えていないことを確認する。空入力も拒否になる。

保存は毎回新規ファイルを作るため、同じ内容であっても新たに承認した要求は別の記録になる。承認後のモデル応答が失敗しても、すでに保存されたファイルは残る。再実行する前に保存先を確認する。

`--trace` は承認の判断と、停止・再開を含む会話全体のツール履歴を表示する。`requests` は再開前後の合計。1つの質問についてモデル要求12回、実行ツール24回を上限にしている。

### 第1回（素のLLM）とエージェントの回答の違い

GitHub Codespaces上で、同じ質問「AIE2026の講座の宿題にある『3レベル』とは何ですか？」を `app.ask` と `app.agent` に入力した。どちらもモデルは `gemini-3.5-flash-lite` を使用した。

素のLLMは、一般的な課題設計として「基礎・応用・発展」を説明し、AIの処理の3階層を指す可能性にも言及した。本講座の定義を特定できず、教材や講師への確認を勧めていた。

エージェントは `search_glossary(query="3レベル")` を実行し、本講座の定義に沿って「基礎・実装・発展」と回答した。「どれか1つに取り組めば完了」という条件を説明し、回答の最後に「第1回」と示した。講座固有の知識を検索で取得することで、一般論から本講座に即した回答に変わった。

実行記録：[素のLLM](results/live/ask.txt)、[エージェント](results/live/agent.txt)。

### 追加したツールとdocstring

`make_quiz(lecture: int) -> str` を追加した。指定した回の用語を `load_glossary()` から集め、1つ選んで「○○の意味は？」という問題と、その用語の定義を答えとしてJSONで返す。用語がない回ではエラーメッセージを返す。

docstringには、「第2回の確認問題を出して」のように復習用の問題を求められたときに使う、と記載した。`INSTRUCTIONS` にも確認問題を求められたら `make_quiz` を使う指示を追加した。

Geminiでの実行では `make_quiz(lecture=2)` が呼ばれ、QLoRAについての確認問題が出題された。ツールは問題と答えを返したが、モデルの最終回答では問題だけが提示されていた。

## 宿題

### 取り組んだレベル

実装。

### やったこと

`app/tools.py` に `save_learning_log(lecture: int, content: str) -> str` を追加した。講義回・学習内容・UTCの保存日時を `learning_log/` 内のJSONファイルに保存する。ファイル名は日時とUUIDで生成し、排他的な新規作成で既存ファイルの上書きを防ぐ。空の学習内容や1未満の講義回は保存せず、書き込みに失敗した場合も保存成功を返さない。

`app/agent.py` では、出力型に `DeferredToolRequests` を加え、保存ツールを承認付きで登録した。

```python
agent = Agent(instructions=INSTRUCTIONS, output_type=[str, DeferredToolRequests])
agent.tool_plain(tools.save_learning_log, requires_approval=True)
```

保存が要求されると `DeferredToolRequests` で一度停止する。CLIでツール名・講義回・保存内容・保存先を表示し、利用者に `[y/N]` で確認する。利用者の判断をツール呼び出しIDに対応付けた `DeferredToolResults` と、それまでの会話履歴 `result.all_messages()` を渡して再開する。`y`・`yes`・`はい` の場合のみ承認し、空入力・その他の入力・EOF・入力中断は拒否する。

### Geminiでの実行結果

保存を依頼した内容は、講義回が3、学習内容が「モデルがツール呼び出しを要求し、プログラムが承認後に実行する」。承認と拒否で同じ依頼を使った。

| 条件 | 実行ログで確認した結果 | `requests` | 実行された保存ツール数 |
|---|---|---:|---:|
| 保存を承認 | `[approval]` が `approved`。ツールが `status: saved` とJSONの保存先を返し、モデルも保存成功を報告 | 2 | 1 |
| 保存を拒否 | `[approval]` が `denied`。ツール本体を実行せず `The tool call was denied.` を返し、モデルも保存していないと報告 | 2 | 0 |

承認時には、モデルは「ご依頼いただいた学習内容を、学習記録として正常に保存しました」と回答し、最後に「第3回」と示した。拒否時には「学習記録の保存が拒否されたため、保存は行われませんでした」と回答した。拒否後に同じ保存を再要求する動きは、この実行ログにはなかった。

実行記録：[承認した場合](results/live/save_approved.txt)、[拒否した場合](results/live/save_denied.txt)。

### APIを使わない検証

ローカル環境（Python 3.12.14、pydantic-ai-slim 2.57.0、google-genai 2.31.0）では、講座付属テストと追加テストを合わせて34件すべて成功した。講座指定の `uv.lock` は変更していない。

承認前には保存ディレクトリが作られないこと、承認するとJSONが1件作られて内容が一致すること、拒否・空入力・EOF・入力中断では保存されないことを確認した。複数の保存要求への個別の判断、上書き防止、不正な入力、書き込み失敗、読み取りだけの質問で承認を求めないことも検証した。

この検証は `FunctionModel` などでツール呼び出しを固定したもので、上記のGemini実測とは区別している。検証スクリプトのモデル要求回数は、Geminiへの実際の呼び出し回数ではない。

実行記録：[テスト結果](results/pytest.txt)、[APIなしの実行ログ](results/offline_trace.txt)、[詳細データ](results/offline_results.json)。

### 気づき・疑問

「保存前に確認する」と指示文に書くだけでは、実行を確実に止める仕組みにはならない。`requires_approval=True` により、ツール本体が動く前にプログラム側で停止できる。今回は実モデルでも、承認待ちで停止し、利用者の判断に応じて保存または拒否を処理してから回答を再開できた。

拒否した場合もLLMへの要求は2回発生したが、実行された保存ツール数は0だった。`[tool call]` はモデルからの実行要求を表し、実際にツール本体が実行されたこととは区別して読む必要がある。

また、用語比較の検索が1回だったことや、確認問題で答えを表示しなかったことから、ツールの戻り値と最終回答は同じではないと分かった。回答文だけで完了と判断せず、ツールの引数・戻り値や保存先の状態も確かめることが有効だと考えた。
